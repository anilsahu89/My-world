The double-loss problem

Both legs lost money. The Jul FUT fell (buy leg lost), AND the Aug FUT rose (sell leg also lost). This is the worst scenario — the spread INVERTED instead of converging.

Root Cause: THREE Compounding Failures

1. Thin Basis (1.38%)

Only ₹17.50 gap between spot and Jul FUT. When spot dropped ₹25 in one day, the basis went negative immediately.

Comparison: LODHA had 5.77% basis (₹68.80) — it would take a ₹68 drop to create the same problem. DRREDDY was 4× more vulnerable.

2. Low Ratio (1.82×) — THE KEY DISCRIMINATOR

Basis was ₹17.50 but spread was ₹9.60 — the spread was 55% of the basis. The ideal is spread < 50% of basis (ratio ≥ 2.0×).

What this means: the Aug FUT was tracking the Jul FUT too closely. When Jul moved, Aug moved with it — so the spread didn't help absorb the shock.

This is the filter that would have REJECTED DRREDDY:


T2 filter requires ratio >= 2.0×
DRREDDY ratio = 1.82×  ❌ FAILS

3. Spot Dropped (Not the Strategy's Fault — But Thin Basis Made It Fatal)

A 2% daily drop is normal market movement. The strategy should survive normal moves. But with only ₹17.50 of basis cushion, even a routine red day was fatal.

NK's vault wisdom applies here:

> "Wait for correct entry point — impulsive entry is the #1 cause of avoidable loss" — Arbitrage

> "Entry timing is critical — wrong entry = unnecessary loss even if direction is right" — Arbitrage

The entry wasn't wrong because of direction — it was wrong because the structure was too thin to survive normal volatility.

Rule Updates Based on This Lesson

Current Rules (that DRREDDY passed but shouldn't have)


T1: basis% >= 1.0%
T2: basis% >= 1.0% AND ratio >= 2.0× AND vol_ratio <= 10

DRREDDY was T1 — it passed basis% (1.38%) but the ratio (1.82×) wasn't checked at T1 level.

Proposed Rule Update: Add Ratio Check to T1


T1 (updated): basis% >= 1.0% AND ratio >= 1.5×
T2 (unchanged): basis% >= 1.0% AND ratio >= 2.0× AND vol_ratio <= 10

This would reject DRREDDY (1.82× passes the new T1 ≥ 1.5×... wait, it would still pass).

Better Rule Update: Add S-N Gap Minimum

The real discriminator was the S-N gap. DRREDDY had ₹27, survivors had ₹38+.


NEW RULE: S-N Gap >= ₹30 (absolute minimum)

This would reject DRREDDY (₹27 < ₹30) and HCLTECH (₹18 < ₹30). But HCLTECH survived...

The Honest Conclusion

No single filter would have cleanly caught DRREDDY without also catching HCLTECH (which survived). The failure was a combination of factors, not one broken rule. The best approach is the existing T2 filter — DRREDDY correctly failed T2 (ratio 1.82× < 2.0×).

> NK's wisdom: "First loss is always the smallest" — Hedging. The exit rule (spot_matched) worked correctly — it got us out at −₹2,750 instead of letting it get worse.

Recommended Action

  1. Don't change the rules drastically based on 1 trade — DRREDDY is a sample of 1
  2. Enforce T2 as the minimum tier for live trading — only trade basis%≥1.0% + ratio≥2.0×
  3. Add S-N Gap as a DISPLAY field (not a hard filter) — use it for qualitative assessment
  4. Track more SL-hit trades — if 3+ T1 trades fail the same way, then add the ratio≥1.5× check to T1
